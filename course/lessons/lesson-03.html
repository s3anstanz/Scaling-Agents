Lesson 03 Week 1 · One agent ~14 min 1 agent

Context is the bottleneck

A model can only act on what is in front of it. This lesson looks at what an agent actually sees, why more is often worse, and how a short file of rules does more for a port than a long conversation.

Part oneWhat the agent sees

Every model call in the loop gets one input, called the context: all the text the model reads before writing its next message. The space for it is the context window, which has a fixed size. Think of it as the agent's working memory. Anything outside it does not exist for that call.

For a Claude Code session in kestrel-starter, the context is built from five sources.

  • The system prompt. Claude Code's own instructions and the definitions of the tools it can call. You do not write this one for the main session. You will write your own when you define subagents in Week 2.
  • CLAUDE.md. Loaded automatically at the start of every session. The starter's version is short on purpose: the goal, and six rules (read MIGRATION.md first, verify.sh defines done, never edit the Python, port in dependency order, trust status.py over reports, record traps).
  • Your prompt. The task, plus whatever exit conditions you wrote into it.
  • Files it chooses to read. kestrel/core/color.py, tests/core/test_color.py, MIGRATION.md. The agent decides these, guided by everything above.
  • Tool output. Every command result, test failure and directory listing, appended as the loop runs.

The first three sources are set before the run starts. The last two are where the agent spends its window, and they grow on every pass around the loop. A port of color.py ends with a context made mostly of things the agent decided to read and commands it decided to run.

Part twoWhy reading everything hurts

It is tempting to tell an agent to read the whole repo first so it has the full picture. On Kestrel that would mean all 24 Python modules, their tests and the scripts. It costs three ways.

It costs money on every later call. As Lesson 02 showed, each model call carries the whole conversation. Files read in the first iteration are paid for again in the twentieth.

It buries the detail that matters. The single most important line for porting color.to_gray is the docstring saying it rounds half to even. In a context holding thousands of lines of unrelated ops/ code, that line is easier to miss. Models attend better to a short, relevant context than to a long, mostly irrelevant one.

It fills the window. When a long session gets close to the limit, something has to give. Part four covers what Claude Code does then, and why you would rather not rely on it.

Predict first

errors and mathutil are already ported. To port kestrel/core/color.py well, which files does the agent actually need to read?

The answer

About four. kestrel/core/color.py (the source), tests/core/test_color.py (the behaviour to match), ts/src/core/mathutil.ts (because color imports clamp_byte and round_half_even, and the port must import their TypeScript versions by their ported names), and MIGRATION.md (the rules). It does not need any of ops/, io/ or pipeline/. Note that the useful file for the dependency is the ported one. Rereading mathutil.py would invite the agent to reimplement rounding inline instead of importing the helper that already passes its tests.

Part threeA contract in a file

Ports done in different sessions have to fit together. image.ts will import from color.ts; every op will import from image.ts. If one session names a function toGray and another expects to_gray, the code does not link, even though each module passes its own tests.

A contract is the written agreement every port follows: how names change, how Python types map to TypeScript, where tests go and how they are ported, and which traps to avoid. In the starter, that contract is MIGRATION.md. CLAUDE.md stays short and points to it.

The split is deliberate. CLAUDE.md loads into every session, and in Week 2 it also loads into every subagent, so each line in it is paid for many times over. MIGRATION.md is read when a port begins, by the agents that need it. Keep the always-loaded file to what every task needs and let it point to the rest.

The contract has one more job. Agents do not remember earlier sessions; files do. When the mathutil run in Lab 02 discovered that Math.trunc breaks floor_div, that knowledge lived only in that run's context, and it vanished when the run ended. The Known traps section at the end of MIGRATION.md is where it should go, and the starter's CLAUDE.md already tells agents to add a bullet there when they find a difference. Some of your runs may have started doing it. Once a trap is written there, every later port reads it before writing a line. This is the cheapest form of learning an agent system has, and it scales: in Week 3, a dozen agents will read the same traps list.

Part fourContext rot and compaction

Long sessions degrade in a predictable way, sometimes called context rot. Instructions from the start of the session are still in the window, but they are now a small part of a large context. The agent read color.ts before editing it, so the old version is still there next to the new one. Test output from three attempts ago sits beside the current output. The model has to work out which of these is current, and it does not always get it right.

When a session approaches the window limit, Claude Code compacts it: it replaces older parts of the conversation with a summary so the session can continue. That keeps the session alive, but a summary drops detail. A summary tends to lose the exact failing assertion, the precise line of MIGRATION.md that mattered, and the reason an approach was abandoned.

Three working rules follow, and the rest of the course builds on them.

  1. One task per context. One module per run or session. Porting all of wave L1 in one long session is how you get rot. A fresh run per module is cheaper and cleaner.
  2. Durable facts go in files. Traps, decisions and conventions belong in MIGRATION.md, where every run reads the current version. The conversation is scratch space.
  3. Give each agent the smallest context that is enough. This is the main reason to use subagents in Week 2. Each gets a fresh context with only its task, and only its final report comes back.
Lab 03 · In Claude Code ~20 min · est. $0.50–$2.50

Goal. Port color.py twice, once without CLAUDE.md and once with it, compare the results, then write T1 and T2 into the Known traps section of MIGRATION.md.

  1. From the repo root, activate the environment and confirm the tree is clean (no output from git status).

    source .venv/bin/activate
git status --short

  2. Run the port in bare mode. --bare skips CLAUDE.md (along with hooks, plugins, MCP servers and subagent discovery). The prompt deliberately does not mention MIGRATION.md or the barrel file.

    start=$SECONDS
claude --bare -p "Port kestrel/core/color.py to TypeScript at ts/src/core/color.ts and its tests from tests/core/test_color.py to ts/test/core/color.test.ts. Run scripts/verify.sh kestrel/core/color.py and keep fixing until it exits 0. If the same test fails the same way twice in a row, stop and report the failure instead. Finish with up to five lines: the files you read, and any Python-vs-JavaScript difference you had to handle." \
  --model sonnet \
  --max-turns 20 --max-budget-usd 1 \
  --output-format json \
  --permission-mode acceptEdits \
  --allowedTools "Read,Edit,Write,Glob,Grep,Bash(scripts/*),Bash(./scripts/*),Bash(python scripts/*),Bash(python -m pytest*),Bash(npx vitest*)" \
  > notes/runs/color-bare.json
echo "color-bare $((SECONDS - start))" >> notes/runs/seconds.txt

    If bare mode will not start. Because --bare skips more than CLAUDE.md, it may not use your claude.ai login. If step 3's runinfo shows is_error: True, one turn and zero cost (the JSON result says Not logged in), run mv CLAUDE.md CLAUDE.md.off, run the same command without --bare, and run mv CLAUDE.md.off CLAUDE.md before step 4.

  3. Inspect the bare result and keep a copy of it.

    python scripts/runinfo.py notes/runs/color-bare.json
scripts/verify.sh kestrel/core/color.py; echo "exit=$?"
git status --short
cp ts/src/core/color.ts notes/color.bare.ts

  4. Reset the TypeScript tree and the contract to the checkpoint. The reset leaves notes/ alone, so your records survive; afterwards git status should list only files under notes/.

    git checkout -- ts/ MIGRATION.md && git clean -fdq ts/
git status --short

  5. Run the identical prompt in a normal run, which loads CLAUDE.md.

    start=$SECONDS
claude -p "Port kestrel/core/color.py to TypeScript at ts/src/core/color.ts and its tests from tests/core/test_color.py to ts/test/core/color.test.ts. Run scripts/verify.sh kestrel/core/color.py and keep fixing until it exits 0. If the same test fails the same way twice in a row, stop and report the failure instead. Finish with up to five lines: the files you read, and any Python-vs-JavaScript difference you had to handle." \
  --model sonnet \
  --max-turns 20 --max-budget-usd 1 \
  --output-format json \
  --permission-mode acceptEdits \
  --allowedTools "Read,Edit,Write,Glob,Grep,Bash(scripts/*),Bash(./scripts/*),Bash(python scripts/*),Bash(python -m pytest*),Bash(npx vitest*)" \
  > notes/runs/color.json
echo "color $((SECONDS - start))" >> notes/runs/seconds.txt

  6. Compare the two runs. Check four things: do the exported names follow the naming rules in MIGRATION.md (snake_case becomes camelCase, so to_gray becomes toGray, and colours are readonly [number, number, number]); does toGray import the rounding helper from ./mathutil or reimplement rounding inline (the T1 risk); did the run add an export line to ts/src/index.ts; and how do turns and cost differ?

    python scripts/runinfo.py notes/runs/color-bare.json notes/runs/color.json
diff notes/color.bare.ts ts/src/core/color.ts
grep -n "import\|export" notes/color.bare.ts ts/src/core/color.ts
git diff ts/src/index.ts

  7. Write the traps into the contract properly. This run may only read and edit, and it must change nothing outside Known traps.

    claude -p "Our ports so far met two Python-vs-JavaScript traps. T1 rounding: Python round() sends exact halves to the even neighbour, JavaScript Math.round sends them up. T2 floor division: Python // floors toward negative infinity, Math.trunc cuts toward zero. Read notes/runs/mathutil.json, notes/runs/color.json and the TypeScript in ts/src/core/ to see how each trap was handled, and search kestrel/ for every module that calls round_half_even or floor_div. Then make the Known traps section of MIGRATION.md contain exactly one bullet for each trap, as the section itself asks: start with the label (T1 rounding, T2 floor division), then what differs, which Kestrel modules it bites, and the fix (which TypeScript helper to import from where). If earlier runs already added a bullet about either trap, rewrite that bullet instead of adding a second. Keep any other trap bullets. Change nothing else in the file." \
  --model sonnet \
  --max-turns 12 --max-budget-usd 0.5 \
  --permission-mode acceptEdits \
  --allowedTools "Read,Edit,Glob,Grep"

  8. Review the diff yourself, then checkpoint.

    git diff MIGRATION.md
scripts/verify.sh kestrel/core/color.py; echo "exit=$?"
git add -A && git commit -qm "lab 03: port color, record T1 and T2"
What you should see

Both runs will probably reach exit=0; the tests are the same either way. The differences show up in the shape of the code. A typical bare run names things however it likes, may reimplement rounding with its own helper, and leaves ts/src/index.ts alone. A typical normal run reads MIGRATION.md early (CLAUDE.md told it to), follows its naming, imports the rounding helper from ./mathutil, and adds the barrel line. Your run may differ: some bare runs find MIGRATION.md by exploring, usually at a cost of extra turns. Another difference: the normal run may add a Known traps bullet on its own, because CLAUDE.md asks it to, while the bare run never does. After step 7, Known traps should hold one bullet each for T1 and T2, naming modules such as color and blur for T1 and geometry, resize and rotate for T2.

Stretch

Run the normal port prompt again with --max-turns 6 on a reset tree and see whether a tight cap changes what it chooses to read. Agents under pressure tend to skip the contract first, which is a good argument for putting the most important rule in the prompt as well.

Key takeaway

Give each run the smallest context that is enough, and keep what must last in files. MIGRATION.md is the contract every port reads, and its Known traps section is how your agents learn across sessions.
