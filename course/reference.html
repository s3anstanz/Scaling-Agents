How many agents?

ScaleReach for it whenMain riskClaude Code mechanism
1The work is sequential or tightly coupled, fits in one context, and has a checkable finish line.Stopping early, or looping without progress.One session, a Stop hook gate, --max-turns, --max-budget-usd
3–5A few independent pieces, a need for a fresh-eyed reviewer, or context that would overflow one agent.Lossy handoffs; paying several times the tokens for little speedup.Subagents in .claude/agents/, CLAUDE_CODE_SUBAGENT_MODEL
10–25A dependency graph with wide waves, explicit contracts between pieces, and a status source derived from the repo.Agents overwriting each other; drift between modules that unit tests miss.Worktree isolation, --json-schema results, agent teams (experimental)

Subagent file

---
name: reviewer
description: Reviews a ported Kestrel module against its Python original. Use after every port.
tools: Read, Grep, Glob, Bash
model: opus
effort: high
maxTurns: 25
---
You review one ported module. Read the Python source, the TypeScript port and both
test files. Run scripts/verify.sh on the module. Never edit files. Report PASS or
FAIL with the exact failing cases and any trap from MIGRATION.md the port missed.

Other fields: disallowedTools, permissionMode, skills, mcpServers, hooks, memory, background, isolation: worktree, color, initialPrompt. Subagents start with a fresh context, load CLAUDE.md, and send back only their final report. They can nest 3 layers deep and 20 can run at once by default.

Headless runs

claude -p "Port kestrel/ops/crop.py. Done means scripts/verify.sh kestrel/ops/crop.py exits 0." \
  --model sonnet \
  --max-turns 25 \
  --max-budget-usd 1 \
  --permission-mode acceptEdits \
  --output-format json \
  --json-schema '{"type":"object","properties":{"module":{"type":"string"},"passed":{"type":"boolean"}},"required":["module","passed"]}'

The JSON result includes total_cost_usd, num_turns and structured_output. --bare skips CLAUDE.md, hooks, plugins, MCP servers and subagent discovery. Running several at once is ordinary shell (& and wait, or xargs -P).

Stop hook: make "done" mechanical

{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "python \"$CLAUDE_PROJECT_DIR/scripts/stop_gate.py\"" } ] }
    ]
  }
}

The hook reads JSON on stdin. Exit code 2 (the reason goes to stderr), or printing {"decision":"block","reason":"..."}, sends Claude back to work. Check stop_hook_active so you don't block forever; Claude Code also stops after 8 back-to-back continuations (CLAUDE_CODE_STOP_HOOK_BLOCK_CAP). SubagentStop does the same for subagents.

Workflows

export const meta = {
  name: 'port-wave',
  description: 'Port every module in one dependency wave, then verify each',
  phases: [{ title: 'Port' }, { title: 'Verify' }],
}
const RESULT = {
  type: 'object',
  properties: { module: { type: 'string' }, passed: { type: 'boolean' }, notes: { type: 'string' } },
  required: ['module', 'passed'],
}
const results = await pipeline(
  args.modules,
  m => agent(`Port ${m} following MIGRATION.md. Stop when scripts/verify.sh ${m} exits 0.`,
             { label: `port ${m}`, phase: 'Port', model: 'haiku' }),
  (_, m) => agent(`Run scripts/verify.sh ${m} and report the result.`,
             { label: `verify ${m}`, phase: 'Verify', schema: RESULT }),
)
const ok = results.filter(Boolean).filter(r => r.passed)
log(`${ok.length}/${args.modules.length} modules passed`)
return results
